# Changelog

All notable changes to Siniskalc.
Versions follow [Semantic Versioning](https://semver.org/); a release is made by pushing a tag `vMAJOR.MINOR.PATCH` (see `.github/workflows/release.yml`).

## [Unreleased]

- Internals (no change in behaviour, 2026-11-02): `AppCompositionRoot` builds the components and `AppServices` only holds them; no constructor on the way has an optional parameter that defaults to the real thing (`IGameDefinitionReader`, the game-service decorator, the encoding, the settings path and the logger factory are passed in, by `App` or by the test).
- Logging review of the JSON migration: decoder messages name the actual catalog stand-in, unknown castle factions are traced, and skipped Mage Guild levels produce one warning per castle rather than one per level.
- **Consistent definition organization:** HoMM2 spell categories are in `spellTypes.json`. Both games keep `mines.json`, `visitablePlaces.json`, `visitEffects.json` and `mapObjects.json` under their standard set, with descriptions named consistently and game-specific storage fields preserved.
- HoMM3's Catapult is no longer an artifact definition; editable war machines remain in their separate catalog. HoMM2's similarly named actual artifacts are unchanged.
- **Simpler game definitions:** artifact effects are sparse attribute/amount lists in both games; default artifact and spell flags and ordinary roles can be omitted. Fallbacks use code 0 and the well-known `Neutral` faction is recognized by ID, not authored flags; `Ranged` is a standalone ability. Array position controls display order without an `order` property. HoMM3 visitable definitions are named `visitablePlaces`; all shipped entities now live in `standard`, with version-specific creature stats kept on the record. JSON versions use `roe`, `ab`, `sod`, `chronicles`, `hota` (HoMM3) and `sw`, `pol` (HoMM2).
- **Standard game entities load from JSON in both HoMM2 and HoMM3.** Creatures and abilities, artifacts and supported effects, factions, castle buildings, supported map-object metadata, spells, hero class/faction mappings, secondary skills, spell groupings and war machines (where applicable) now come from the shipped `GameData` folders. Adding content within existing mechanics and savefile capacities needs only definition edits and an editor restart, not new C# identities. Definitions are validated at startup; a missing or invalid file stops startup with the file and cause. There are no custom profiles or live reload. See `docs/GAME_DEFINITIONS.md`.
- **Fixed (HoMM2): giving a hero to another player named it by its portrait byte in the player's list of heroes**, and "Send to" took a hero's own castle for a taken one; both now use the hero's place in the savegame. It showed in scenarios whose heroes carry another portrait than their place (such as `MapDifficultySize` save 07).
- **HoMM2: the pending changes list the places a hero visited one kind at a time** ("Visited: forts") as HoMM3 does, instead of one "Places visited" total; the morale and luck of the next battle read the same in both games, and a player's tavern is listed before its days left.
- Internals (no change in behaviour, 2026-10-31): both games use one `SavegameService<Game>`; the Mage Guild spells of a HoMM2 castle are `Spell`s in the model (a byte that is no spell is still left alone when the file is saved); a neutral creature has the Neutral faction instead of `null`; "Moved today" is shown by what the savefile can hold, not by the game version; one row builder for the places a hero visited.
- **A log file, with a Settings page for it.** The editor writes a plain text log (`siniskalc-<date>.log`, 7 days kept) of what it did and of every value it did not know and read as a stand-in, to `%LOCALAPPDATA%\Siniskalc\logs` (Linux and macOS: `~/.local/share`). **Help > Show logs** opens the folder; **Settings... > Logging** sets the level and the folder (applied at the next start). How the log is written (template, sinks, rolling interval, days kept) is in `serilog.json`, written beside `settings.json` on the first start together with the default settings; a settings file or a `serilog.json` that cannot be read is reported at start-up with an offer to reset it. See the user guide and `docs/LOGGING.md`.
- **HoMM3: changing the owner of a hero keeps the rest of the save in step.** The players' lists of heroes (count, the ids, the selected hero) and the game's table of hero owners (one byte for each hero: the player that owns it, free, or in a tavern) change with the hero, in one undo step, and the change is listed in the pending changes (it was not before). A hero that is free and in no tavern can be given to a player (up to 8 heroes; a full list is refused); a hero in a tavern (the game refills the slot at random), a campaign hero and a garrisoned hero are refused with the reason. Found in the saves of `TestData/Hota/HeroOwners` (defeats and hires of one map).
- **HoMM3: giving a castle to another player starts or ends the banishing countdown**, as the game does (the player that loses its last town gets 7 days, one that regains a town is no longer counted; a banished player is left alone). The HoMM2 castle and hero owner change now reverts in one step with the players' lists. A castle's **Allow / Disallow** of a building is a pending change in HoMM3.
- **HoMM3: the morale and luck of the next battle and the buildings a hero visited today can be edited** (watering hole, swan pond, crypt, stables; not tried in the game). **Dwellings show the weekly growth of their creature** ("+N a week", the base growth) and **mines and dwellings show the level of the map** (surface or underground); the give-the-turn button is shown disabled with the reason, as the editor does not write the turn for HoMM3 yet.
- **HoMM2: the player page has a Banishing card to set the days left** (the same card as in HoMM3); the primary skills show base, total and the artifacts' share; the tree shows a castle badge and the visiting hero; the map page has a Bytes tab for the records of mines, shrines, sphinxes, the turn, built-today and obelisks; the Visions box is shown disabled because the editor does not know where the game keeps it.
- **Pending changes read alike in both games**: a hero's experience and level are one change ("Experience 1,500 (level 3)"), the position includes the facing and the level of the map, the destination reads "none" or "X: 30, Y: 30", the movement shows what is left out of a full day, spell points have a thousands separator; the tavern of a player lists each place with the name of the hero; a change of the days left is listed in HoMM3 too.
- Internals (no change in behaviour, 2026-10-23/24): one set of blocks for the obelisk page, the army editor, the secondary skills editor, the mines tab, the days-left card, the lists of what a colour owns, the primary skills card, the pending changes of a player and of map objects; the records of the map are one generic stack in Core; the Heroes editors moved from `Siniskalc.Wpf` to `Siniskalc.Heroes.Wpf`; `IGameInfo` and `GameSetup<TColor>` are shared; the per-game marker interfaces that only closed a Core generic are gone; StyleCop member order is clean in every project.
- **HoMM2: a Mage Guild slot offers the spells of its guild's level** (level N teaches level N spells, as every guild of the test saves does); a spell of another level that the savegame holds there is still shown and kept. **The levels of 20 HoMM2 spells were corrected** to what the guilds and shrines of the saves hold (Magic Arrow 1, Armageddon 5, the guardians 4, ...), which also changes the Level column of the spell finder. The rule is the editor's, not proved to be the game's: the game itself showed a level 5 spell in a level 1 guild in the E18GUILD write test.
- **HoMM3: the "Order of play" buttons give the turn. NOT TRIED IN THE GAME YET: test it before relying on it.** Pressing the button of a human who has not the turn makes it that player's turn: it writes the colour after the human flags of the setup, the one value that changed with the turn in 21 pairs of consecutive test saves. It is a pending change that can be undone, and a computer player cannot be given the turn. The tooltip says it is not tried; the probe is in `docs/FUTURE_IMPROVEMENTS.md`.
- **Fixed (HoMM3): Red and Blue had no page in some savegames.** In the saves of the four-player test map the player table was not found for them (a flag byte of their struct that is 0 there and 1 elsewhere was part of what the loader looked for), so the General tab, the banishing counter and everything else of the two players were missing. The saves are `TestData/Hota/Banishing` 14 to 16 (Blue counts 7, 6 days and is banished).
- **HoMM3: the places card has "All none" and "All visited" at the top**, and the trees of knowledge are listed with where they are. The map page lists **every black market of the map** with its tile (`TestData/Hota/multi_merchants` has four); the number in front of the lists is the number of merchants.
- **HoMM2: a castle shows its weekly growth and whether it can still build today.** Each dwelling says how many creatures it gains a week (the growth of the creature, +2 from the Well, and +8 more in the first dwelling from the faction's second well: Farm, Garbage Heap, Crystal Garden, Waterfall, Orchard, Skull Pile; an unbuilt dwelling gains nothing), and a "Can build this turn" box at the top of the Buildings tab, as in HoMM3, reads and writes the game's one-building-a-day flag. The flag is a set of 72 bits after the table of castles, cleared when a new day starts (saves of `TestData/Homm2/BuiltThisTurn` and `SecondWell`). Not yet tried in the game.
- **HoMM2: more of the savegame is understood and editable** (from the 71 saves of `TestData/Homm2/Threedom`): the towns' marketplace, turrets, moat, captain's quarters, the second well and the special building of each faction (Library, Storm, ...); the morale and luck a hero has for its next battle; and the places a hero has visited (forts, gazebos, huts, camps, standing stones), which can be forgotten so that the hero visits them again. Not yet tried in the game.
- **HoMM2: the hero page lists the places it visited with where they are** (forts, gazebos, witch doctor's huts, mercenary camps, standing stones, Xanadu), to forget or remember one at a time; it also shows what the hero remembers of the fountain, oasis, faerie ring, graveyard, temple, arena and stables. **The player page has the obelisks of the map**, as Heroes of Might and Magic III does, with their coordinates. Found in the 82 saves of Threedom; not yet tried in the game.
- **HoMM2: the player pages and the overview say who plays each colour** ("Human" or "Computer") and whose turn it is, read from the header (saves of `TestData/Homm2/HumanCpu`: one, four and six humans). Shown only; changing it is not offered until a save made in the game proves it is safe. `PlayerType` and its wording moved to `Siniskalc.Heroes` so both games share them.
- **Fixed (HoMM2): the players of a savegame where a human does not play Blue.** The game stores the player records in the order the players play, humans first (a game with Green and Orange human has Green, Orange, Blue, ...), and the editor took the first record for Blue: the resources, heroes and castles of one colour were shown under another. Each record says its colour, and the editor now uses it. Found with the hot seat saves of `TestData/Homm2/HumanCpu`.
- **An "Order of play" card on the overview** lists the players in the order they play, a button each, with the one whose turn it is lit in bronze. In HoMM2 pressing the button of another human gives that player the turn (it writes the number of the player's record, the byte the saves of `TestData/Homm2/HumanCpu` show moving from player to player; not yet tried in the game); computers cannot be given the turn. HoMM3 shows the same card; its buttons can be pressed but change nothing yet.
- **HoMM3: a Merchants tab on the Map page shows what the artifact merchants and the black market have in store**: seven slots each, picked like the artifact of a hero; a cleared slot is an artifact that was sold. Found in the saves of `TestData/Hota/VisitedPlaces` (a purchase empties its slot). Not yet tried in the game.
- **HoMM3: the Map page has a Dwellings tab** (found in the Horn of the Abyss saves of `TestData/Hota/Dwellings`): each creature generator of the map with the creature it gives, where a hero stands to flag it, its owner, which can be changed, and **how many creatures can be hired there now**, which can be typed. They can be sorted by creature, owner, location and the creatures to hire. The table was found while Tazar and Orrin flagged and hired from the dwellings of the Castle and the Rampart. Not yet tried in the game.
- **HoMM3: a Places tab on the hero page lists the places of the permanent bonuses the hero visited** (learning stones, Marletto towers, gardens of revelation, mercenary camps, star axes, trees of knowledge, libraries of enlightenment, arenas, schools of magic and of war, and in Horn of the Abyss the colossi and the gazebos), with the places of the map by position to forget or remember one at a time. It is the card HoMM2 has, shared. Found in the Horn of the Abyss saves of `TestData/Hota/VisitedPlaces`: each hero keeps a bit for each place of a kind. Not yet tried in the game.
- **HoMM3: a Map page lists the mines of the map** (found in the Horn of the Abyss saves of `TestData/Hota/Mines`): each mine with its kind, the tile its record gives and its owner, which can be changed, and the creatures that guard it (an abandoned mine has some until it is taken), which are edited with the army editor of a hero. The mines can be sorted by resource, owner and location. The tile is not where the mine is entered, which is still being worked out. Not yet tried in the game.
- **The destination and the facing of a hero** (the tile it is going to, which the game marks on the map, and the direction it faces) are read, shown and editable on the hero page in both games; HoMM3 calls its "marker" the destination now. Heroes of Might and Magic II had them in the savegame all along (MarkerFacing saves 83 to 93). The two cards are built by the same code in `Siniskalc.Heroes.Wpf`.
- **HoMM2: a Map page lists the mines, the shrines and the sphinxes of the map.** Each mine shows its kind, where it is and its owner, which can be changed (the record and the flag on the map are written together); each shrine shows its circle, its position and the spell it teaches, which can be changed; each sphinx shows whether its riddle can still be answered, the reward, the answers and the riddle, all editable within the room the savegame has. Found in the Threedom saves; not yet tried in the game.
- **Fixed: the primary skills of a HoMM3 hero.** The savefile holds a hero's attack, defense, spell power and knowledge with the bonus of the equipped artifacts already in them (Edric goes from 2/2/1/1 to 11/11/9/9 when he puts on Titan's Thunder), and the editor added the bonus again: the "Total" of the General page and the maximum of the spell points were too high, and putting an artifact on in the editor did not change the skills as the game does. The saved skills are now what counts, the stepper edits what is left without the artifacts (the base), and putting an artifact on or taking it off moves the skills by what it adds, so the pending changes list the skills too. Found with the Arts saves (`docs/KNOWLEDGE_BASE.md`); the bonus table is checked against the game only for Titan's Thunder and Armageddon's Blade (2026-10-15).
- **The pages of HoMM2 and HoMM3 look and work the same**: the header, the tabs, the resources, the cards and the owner picker are shared blocks (`Siniskalc.Heroes.Wpf`). The HoMM2 castle page has the tabs of the HoMM3 one (Buildings, Garrison, Available creatures, Mage guild, Hex) and its header (faction, owner, position, the hero inside, the owner picker); what nobody owns is "Neutral" in both games; the pending changes of a HoMM2 hero say "Creatures" and "Primary skills" / "Secondary skills" where they said "Army" and "Skills". The HoMM3 castle page shows the heroes inside before the "edited" mark. None of it has been seen in the game beyond the tests that open the pages (2026-10-15).
- Internals (no change in behaviour): the HoMM2 types lost their `Homm2` prefix; the editor shell (loading, saving, undo, the navigation tree, the editor view) is shared by the two games (`Siniskalc.Wpf`); the new projects `Siniskalc.Heroes` (what the games share: values, and the interfaces of colours, factions, skills and pages) and `Siniskalc.Heroes.Wpf` (the styles and blocks of the pages). See `docs/SINISKALC_ARCHITECTURE.md`, "Adding a game" (2026-10-14).
- **Banishing**: a player who owns no town shows how many days are left before the game banishes him: a pill beside the name on the player page ("No towns: 6 days left", "Banished"), the same pill on the player's card in the game overview, and "6 days left" after the player in the navigation tree. The first tab of the player page is now called **General**, and for such a player it has a Banishing card with the buttons 7 to 1 to change the days left; a banished player cannot be edited. The days are byte 22 of the player struct (`docs/KNOWLEDGE_BASE.md`) (2026-10-13).
- **Heroes of Might and Magic II** (work in progress): the new project `Siniskalc.Homm2` reads and writes the savegames of the base game (`.GM1`) and of the Price of Loyalty (`.GX1`): heroes, players and castles, with undo and pending changes. The application opens them next to the HoMM3 ones: the shell picks the game from the file and the window title follows it. The editor has the same layout as the HoMM3 one (navigation tree of players, heroes and towns, tabs, "edited" marks and Reset); its pages edit the resources of the players, the heroes (skills, army, spells, artifacts) and the castles (owner, buildings, dwellings, garrison, Mage Guild). Each page has a hex tab in advanced mode, and "Save as" refuses a name the game would not list (more than 8 characters before the extension). None of it has been tried in the game yet beyond the saves of the write test (see `docs/HOMM2_PLAN.md`). The format is in `docs/HOMM2_SAVE_FORMAT.md` (2026-10-12).
- `RawSavefileCodec` in `Siniskalc.Core` reads and writes a savegame that is not compressed.

- The HoMM3 code moved from the exe into the library `Siniskalc.Homm3` (namespaces `Siniskalc.Homm3.*`), and its tests into `Siniskalc.Homm3.Tests`; the exe `Siniskalc` keeps `App` and `AppServices`. No change in behaviour (2026-10-12).
  This prepares support for Heroes of Might and Magic II (`docs/HOMM2_PLAN.md`).
- The window, the menus and the file commands are a game-neutral shell in `Siniskalc.Wpf` (`ShellWindow`, `ShellViewModel`, `SavegameFileCommands`); a game is an `IGameModule` with an `IGameEditor`, and the HoMM3 editor is one of them. The menu icons moved to `Siniskalc.Wpf/Resources`. No change in behaviour (2026-10-12).

- Test savegames were renamed to the rules in `TestData/README.md` (2026-10-12).
  Old names were like `0_roe_tests_baseline`, `4_roe_cita`, `15_dwell_3`, `1_arts`, `111` to `214` or `2PHotseat/_GAME_BEGIN`; `git log --follow` on a save shows its old name.
  Where the new name is a guess, the folder's `README.md` says so.
